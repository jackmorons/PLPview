# PL App: build brief for a Claude Code agent

You are building an iOS app for Jack, a powerlifter and mechanical design engineer based in Italy. The app imports a training program from an `.xlsx` file with a strict layout and shows it as an interactive week/day viewer. Maxes can be edited and saved, and every load recalculates from them. Training tools (RPE, rep totals, plates, timers) are included. Session logging is not: Jack uses a separate logger.

**Delivery:** **one project** built with **Capacitor**.
- The app is a single web app (HTML/CSS/JS).
- Capacitor copies it into two native shell projects: `ios/`, which Jack builds in **Xcode** for his iPhone, and `android/`, which he builds in **Android Studio** for Android devices.
- No native code is written by hand unless §2 says so.
- Jack is a mechanical engineer, not a mobile developer. He wants to **understand what he's doing**, so explaining as you build is part of the deliverable (§8).

## 1. Background (so you don't "fix" deliberate choices)

- PL27 (previous block) ended at a meet: **squat 192.5 / bench 130 / deadlift 220** (total 542.5). Jack was very happy with how its fatigue was managed, so PL28 keeps PL27's structure and notation.
- PL28: **20 weeks, no meet, 5 days (A–E)**, sessions of 2–3 h. Training days are variable: Jack picks the order.
- Priorities added in PL28, with aesthetic goals as important as strength: lateral and anti-rotation core, lat volume, posterior chain (hamstrings/glutes), bigger biceps, serratus anterior, grip strength and forearm size.
- Structure: 4 blocks of 5 weeks. Weeks 5, 10 and 15 are lighter weeks ("transizione"): accessories drop 1 set and get RIR +1. Week 19 has heavy openers ("entrata", about 92%). Week 20 is an optional "TEST" on day D.
- Day E is upper-body hypertrophy with no barbell lifts.
- **Day-order rules** shown in the app:
  1. Never do E (or any heavy grip work) the day before B or D.
  2. B and D never on consecutive days.
  3. Preferably A and D not on consecutive days.
  - Typical order: `A – B – E – C – off – D – off`.
- The program text is in **Italian** and uses Jack's notation, and the app UI should be in Italian too. Keep the program strings exactly as written; never translate or normalize them.

Notation (show it in the app as a reference card):

| Term | Meaning |
|---|---|
| `RT` | Total reps at that load, split into sets however you like (e.g. `160kg 25-30RT`) |
| `ist.` | "Istintiva" set: as many reps as feel right, close to an AMRAP |
| `@7` | RPE 7; `@7/8` means between 7 and 8 |
| `90%` | Percentage of **that day's top set**, not of the max |
| `EMOM n` | One rep at the start of every minute for n minutes |
| `MAV n` | Pull-up scheme carried over from Jack's previous programs; display as written |
| `no var.` | The competition lift with no variation |

## 2. Architecture (Capacitor: one codebase, two native shells)

### 2.1 The mental model (put this at the top of `docs/HOW-IT-WORKS.md`)

```
src/  (YOUR app: HTML/CSS/JS)      ← you only ever edit this
   │  npm run build   (Vite bundles it into dist/)
   ▼
dist/                              ← generated, never edit
   │  npx cap sync    (copies dist/ + plugin code into both shells)
   ├──────────────►  ios/      → open in Xcode          → ▶ Run on iPhone
   └──────────────►  android/  → open in Android Studio → ▶ Run on Android
```

- The app runs inside the system web view on each phone. Capacitor adds a JS → native bridge, so the web code can call phone features (files, haptics, share sheet) through **plugins**.
- `ios/` and `android/` are real native projects. They are generated once by `npx cap add`, then committed. Only touch them for platform settings, such as permissions or the file types the app can open.
- Use the **current stable Capacitor major** (check npm at start; don't use a pre-release) and pin every dependency version in `package.json`.

### 2.2 Project layout

```
pl-app/
  package.json            scripts: dev, build, test, sync, ios, android
  capacitor.config.json   appId "it.jack.plapp" (ask Jack), appName "PL", webDir "dist"
  vite.config.js
  index.html
  src/
    main.js               app bootstrap + tab routing
    parser.js             xlsx → program model (NO DOM, NO Capacitor imports; pure)
    resolve.js            template + maxes → display strings, plates, rounding (pure)
    tools.js              RPE chart, back-off, RT counter logic (pure)
    storage.js            ONE wrapper: Capacitor Filesystem on device, localStorage in browser
    native.js             ONE wrapper over plugins: pickFile, haptic, keepAwake, share
    ui/                   view modules (session, tools, note, programs)
    styles.css
    fonts/                Barlow Condensed, IBM Plex Sans, IBM Plex Mono (OFL), local @font-face
  tests/                  Vitest: parser + golden test against PL28 + tools
  fixtures/               PL28.xlsx, PL28_standalone.html, PL27.xlsx, broken copies
  docs/
    FORMAT.md             import contract (§3)
    HOW-IT-WORKS.md       for Jack (§8)
    BUILD-IOS.md          step-by-step, screenshots optional
    BUILD-ANDROID.md      step-by-step
  ios/  android/          generated by Capacitor, committed
```

**Rule:** only `storage.js` and `native.js` may import Capacitor. Everything else is plain JS. The app must also run in a desktop browser with `npm run dev`; in the browser, `native.js` falls back to `<input type=file>`, no haptics, and so on. That browser mode is Jack's fast development loop.

### 2.4 Other requirements

- **No network at runtime.** SheetJS (community edition, pinned) is bundled by Vite from npm, and the fonts are local. The prototype loads Google Fonts; the app must not.
- **Toolchain** for Jack to install (write it in the build docs, with versions):

- Use Vite's plain JavaScript template: no framework, no TypeScript (Jack should be able to read every file).
- Keep `parser.js`, `resolve.js` and `tools.js` pure so Vitest can test them in Node.

## 3. Import format spec, version 1 (strict)

`PL28.xlsx` is the reference implementation of this spec. Write it up as `docs/FORMAT.md` in the repo. **The parser either accepts the file completely or rejects it.** On rejection, list every problem with its sheet, cell and the reason, in Italian, e.g. `overall!D7: formula non riconosciuta`. Never show a half-parsed program.

Read workbooks with SheetJS using `{cellFormula: true}`, so you get both the formula (`cell.f`) and the cached value (`cell.v`).

### 3.1 Sheets

| Sheet | Required | Notes |
|---|---|---|
| `Massimali` | yes | Lift maxes |
| `overall` | yes | Main-lift plan |
| `accessori` | yes | Accessory exercises |
| `note` | no | Free text in column A, one paragraph per row. Shown in the app's "Note" tab |
| anything else (`volume`, `training log`, …) | ignored | |

Sheet names must match exactly (case-sensitive).

### 3.2 `Massimali`

- Scan column A from row 1 down. A **lift row** has text in A and a number greater than 0 in B. Stop at the first row whose A is `Totale`, or at two empty rows in a row. Ignore title rows (text in A, nothing in B).
- Each lift row is identified by its **row number**, because formulas in `overall` point at `Massimali!$B$<row>`. In PL28: row 3 = Squat, 4 = Panca, 5 = Stacco.
- The maxes in the file are the **defaults**. Edits made in the app are stored per program and override them. Add "Ripristina dal file" to reset to the file's values.

### 3.3 `overall`

- **Row 1 (headers):**
  - `A1` = `week`, `B1` = `fase`.
  - `C1` onwards: each header must match `^(.+?) \(([A-Z])\)$`, i.e. a lift-slot name followed by the day letter in brackets, e.g. `Squat stress (A)`.
  - Columns end at the first empty header.
- **Rows 2 onwards** come in two kinds:
  - **Block row:** A is empty and B is not empty. B holds the block name (e.g. `Blocco 1 – Accumulo`). Cells C onwards hold that block's **variant** for each column (e.g. `discesa 4''`, `no var.`). The first row after the headers must be a block row.
  - **Week row:** A is an integer. Weeks must be consecutive and start at 1 across the whole sheet. B holds the **week type** from the fixed list in `FORMAT-COACH.md` §9 (`normale`, `scarico`, `transizione`, `ramping`, `intensificazione`, `picco`, `taper`, `entrata`, `test`, `gara`; empty = `normale`). Any other value is an error. Cells C onwards hold the prescriptions.
- Blocks may differ in length. Block count and weeks per block come from the file. **Nothing is hard-coded to 20 weeks, 4 blocks or 5 days.**
- An empty prescription cell means that slot isn't trained that week. Hide it.
- **Prescription cells** are one of two kinds:
  1. **Plain text.** Show as written. `—` means not trained that week.
  2. **A formula**, which must match this grammar exactly:
     ```
     formula  := term ( "&" term )*
     term     := string | load
     string   := '"' ( any char, with "" as an escaped quote )* '"'
     load     := "MROUND(Massimali!$B$" ROW "*" NUMBER "," NUMBER ")"
     ```
     Real examples from PL28:
     ```
     ="4x5 + ist. "&MROUND(Massimali!$B$3*0.57,2.5)&"kg"
     ="1x1 "&MROUND(Massimali!$B$4*0.885,2.5)&"kg + 5x3 "&MROUND(Massimali!$B$4*0.845,2.5)&"kg"
     ```
     SheetJS returns `cell.f` without the leading `=`. Allow extra whitespace and either `$` style in the reference, but nothing else. `ROW` must be a lift row found in `Massimali`.
     - Store each formula as a **template**: a list of text pieces plus `{liftRow, pct, step}` load tokens. Compute the loads at render time from the current maxes.
     - Rounding: `MROUND(x, step)` = `Math.round(x / step) * step`. Excel rounds halves away from zero, which gives the same result for the positive values used here.
     - If a cell's formula doesn't match the grammar, it's an **error**. Never silently fall back to the cached value, because the load would then ignore edited maxes.
- **Text tokens as an alternative to formulas.** Accept `{S.57}`-style tokens inside plain text. The letter is the first letter of a `Massimali` lift name (S = Squat, P = Panca, D = Stacco) and the number is the fraction (`.57` = 57%), rounded to 2.5. If two lifts share a first letter, that's an error. This lets Jack hand-write programs without formulas. PL28 doesn't use tokens, but the prototype's `DATA` does, so check the prototype's `resolve()` function for the exact behavior.

### 3.4 `accessori`

- Row 1 headers. The first six must be exactly: `Giorno | Esercizio | Istruzioni | Gruppo | Rep | Intensità`.
- They are followed by **N columns whose header starts with `Serie B`**, one per block in order. N must equal the number of block rows in `overall`, otherwise it's an error.
- Data rows start at row 2 and end at the first row with an empty `Giorno`; ignore everything below. In PL28 a footnote sits below a blank row.
- `Giorno` must be a single capital letter. The **set of days** is the union of the day letters from the `overall` headers and from this column. That's how PL28 gets day E, which has no main lifts.
- Each `Serie Bn` value must be an integer of 0 or more; 0 means not done in that block.
- **Volume-only rows:** a row whose `Intensità` is `vedi overall` counts toward volume but isn't listed with the accessories. In PL28 this is weighted pull-ups, which already appear in `overall`.
- **Sets in light weeks:** in any week whose type is `transizione`, `scarico` or `test`, show `sets − 1` and add a banner saying to keep RIR +1. Hide the exercise if the result is 0. Display format: `${sets}×${Rep}` plus the intensity, as the prototype does.

### 3.5 Internal program format (JSON)

The parser's output is a versioned JSON program defined in `docs/PROGRAM-SCHEMA.md`, starting at `schemaVersion: 1`. **That JSON format is what the app stores and renders, not the xlsx.** Requirements:
- Rules that don't depend on the file format live in `validateProgram(model)`. The parser keeps only xlsx-specific checks.
- `migrate(model)` exists from v1 onward.
- A workbook with no `meta` sheet counts as format v1.

See `VERSIONS.md` → Foundations for why.

### 3.6 Program identity and revisions

- **Program id:** a random UUID assigned at first import. It is **not** derived from the file contents, because an updated file must keep the same program.
- **Revisions:**
  - Each program stores a list of **revisions** `{revisionId, fileName, sha256, importedAt, model}`.
  - The newest revision is the one shown.
  - Keep the last 5 revisions and drop older ones.
- **Display name:** the file name without extension (e.g. `PL28`) at first import. It can be renamed in the app afterwards.
- **Duplicates:**
  - A file whose SHA-256 matches a revision already stored, anywhere, gets the message "già importato" and offers to open that program.
  - A new file whose name matches an existing program asks: **"Aggiorna PL28" / "Importa come nuovo programma"**.
- **What carries over when a program gets a new revision:**
  - Maxes are kept for lifts whose names still match. New lifts take the file's value. Lifts that were removed are dropped.
  - The last week/day viewed is kept, clamped to the new length.
  - Per-program settings are kept (priority groups, etc.).

## 4. App features

### P0: viewer (match the prototype)

1. **Header:** program name; editable max per lift, saved as you type; total.
2. **Week selector:** grouped by block with the block name. Light weeks styled as in the prototype (dashed border, amber). Tooltips for entrata/TEST.
3. **Day selector:** one button per day, color-coded by IPF plate color (A red, B blue, C yellow, D green, E grey; any further letters cycle through the palette) with a short subtitle. Build the subtitle from the day's main-lift names; for a day with no main lifts use `Ipertrofia / accessori`.
4. **Session view** (as the prototype):
   - Title `Settimana N · Giorno X`; pills for block, phase and counts.
   - Phase banners.
   - The **day E reminder** ("Fai E solo se domani non c'è B o D"). For a general program, show it on any day that has accessories but no main lifts.
   - Main lifts: slot name (header without the day suffix), the block's variant, the resolved prescription in monospace, and a plate diagram per side for the heaviest kg in the string. Skip the diagram for slots whose name starts with `Trazioni` (that load is added to bodyweight).
   - Accessories table: exercise, instructions, sets×reps, intensity, group tag. Priority groups get the accent color; make the priority list a per-program setting, with PL28's six groups as its default.
5. **Prev/next** step through every week and day in order. Remember the last week and day. Swipe left/right on the session view does the same.
6. **"Note" tab:** shows the `note` sheet text, the notation card (§1) and the day-order card.
7. **Light and dark theme** following the system, using the prototype's token values.
8. **Import errors screen:** the full list from §3, copyable.
9. **Programs tab** (switch programs and replace files):
   - **List** of all programs, showing for each: name, active badge, number of weeks and days, date of the latest revision and its source file name.
   - **Switch the active program** with one tap. Session, Tools and Note always show the active program. The app opens on the active program at its last week/day. With no programs, the first screen is a designed empty state with the "Importa programma" button.
   - **"Importa programma"** adds a new program and makes it active (ask first if another one is active).
   - **"Aggiorna da xlsx…"** (on each program) replaces the program's file with a newer xlsx. The flow:
     1. Pick the file.
     2. The file is parsed and validated. If it fails, the current revision is untouched and the errors screen is shown.
     3. If it passes, show a **change summary** before confirming:
        - change in the number of weeks/blocks/days
        - main-lift slots added or removed
        - number of prescription cells changed
        - accessories added or removed
     4. On confirm, store a new revision and carry over maxes and position (§3.6).
   - **Revision history** per program: the list of revisions with date and file name, and "Ripristina" (restore) to make an older one current. Restoring adds it as a new revision, so nothing is lost.
   - **Rename, duplicate, delete.** Delete asks for confirmation inside the app (no system `confirm()`) and removes all revisions and maxes of that program.
   - **Export the original file:** re-export the stored source xlsx of any revision through the share sheet. Keep the original file bytes for each revision for this reason.

### P1: training tools (Jack's request: "rpe/rep total etc." — none of these store logs)

Open each tool from the relevant prescription, prefilled, and also from a "Strumenti" tab.

1. **Back-off calculator.** For prescriptions with `NN%` (e.g. `4@7 + 90% 3x4`), tapping opens a sheet: enter the top-set load you actually used → shows the back-off load for every `%` in the string, rounded to 2.5, with plates. Also handle `stesso peso` / `stesso carico` (same load as the top set).
2. **RPE calculator.** Uses the common RTS-style percentage chart:
   - Use this sequence `P` (% of 1RM): `100, 97.8, 95.5, 93.9, 92.2, 90.7, 89.2, 87.8, 86.3, 85.0, 83.7, 82.4, 81.1, 79.9, 78.6, 77.4, 76.2, 75.1, 73.9, 72.3, 70.7, 69.4, 68.0, 66.7, 65.3, 64.0, 62.6`.
   - Index = `(reps − 1) × 2 + (10 − RPE) × 2`, valid for reps 1–10 and RPE 6–10 in half steps.
   - Modes:
     - **e1RM:** load × reps @ RPE → estimated max, with a button to replace the stored max (with a confirmation).
     - **Target load:** reps @ RPE → load from the current max, rounded to 2.5.
     - `@7/8` → use 7.5.
   - Put the chart in a single constant so it can be swapped later.
3. **Rep-total (RT) counter.** For prescriptions matching `(\d+)(?:-(\d+))?\s*RT`:
   - Tap +1…+10 buttons per set, with undo.
   - Shows the running total, the sets done and a progress bar against the min–max range; turns green at the minimum and shows a stop marker at the maximum.
   - The state lasts for the current week/day only and resets on the next session. This is a counter, not a log.
4. **Plate calculator.**
   - Settings: bar weight (default 20 kg), collars (default none; option 2.5 kg each), available plates (default 25/20/15/10/5/2.5/1.25 kg, and 0.5 kg if enabled).
   - The same settings drive the diagrams in the session view.
5. **Ramping helper** (for `ramping ladder`, `ladder`): from a target load, suggest warm-up steps at about 50/70/80/90%, rounded. Show only the numbers.

### P2

1. **EMOM / interval timer.**
   - For `EMOM n`: n rounds of 60 s, with a haptic tick plus an optional sound at each minute.
   - Big minute counter; the screen stays awake while it runs.
   - Sound starts only from a tap (WebKit autoplay rules).
2. **Rest timer**, with presets of 2/3/4/5 min.
3. **Volume view:** weekly sets per `Gruppo` per block, computed from `accessori`, including volume-only rows. Same numbers as PL28's `volume` sheet:
   - B1: Dorsali 16, Bicipiti 11, Serrato 8, Avambracci/presa 9, Femorali/glutei 16, Core laterale/rotazionale 14.
4. **Backup:** export and import all programs, maxes and settings as JSON via the share sheet.

### Non-goals

- Session logging.
- Cloud sync or accounts.
- Editing the program in the app (Jack edits the xlsx and re-imports).
- App Store or Play Store publishing.

## 6. Parser robustness

- Trim cell strings; convert non-breaking spaces to normal spaces.
- Week numbers can come back as `1` or `1.0`, and both are valid. Reject `1.5`.
- Merged cells: treat as an error if they occur in `overall` or `accessori`.
- Errors are shown in Italian, with the cell reference (`overall!G9`).

## 7. Acceptance tests (required)

Write these as Vitest tests against `parser.js`, `resolve.js` and `tools.js`. Also write a manual checklist in `docs/`; Jack runs it **on both an iPhone and an Android device**.

1. **Golden test.**
   - Import `PL28.xlsx` with maxes 192.5 / 130 / 220.
   - Extract `DATA` from `PL28_standalone.html` and resolve every `cols[i].w[week]` with the prototype's own `resolve()` logic.
   - For every week (1–20) × column, the app's resolved string must equal the prototype's, apart from decimal formatting (compare with numbers normalized).
   - Spot checks:
     - week 1 `Squat stress (A)` → `4x5 + ist. 110kg`
     - week 6 `Panca stress (B)` → `1x1 115kg + 5x3 110kg`
     - week 13 `Stacco stress (B)` → `1-ist.-1-ist. 195kg`
     - week 15 `Stacco stim. (D)` → `3x2 160kg`
2. **Maxes recalculate.** Set squat to 200 → week 1 `Squat stress (A)` shows `4x5 + ist. 115kg` (200 × 0.57 = 114, rounded to 115).
3. **Accessories.**
   - Week 1 day A lists Affondi, Leg extension, Side bend, Side plank, and **not** the pull-up row.
   - Week 5 day A shows Affondi as `2×8-10`.
   - Week 10 day C hides nothing that has more than 1 set.
4. **Days.** PL28 gives days A, B, C, D, E; day E has 0 main lifts and 11 accessories in block 1.
5. **Rejections.**
   - `PL27.xlsx` is rejected with sheet-level errors.
   - Copies of PL28 with a broken `accessori` header, a non-integer week, a `MROUND` pointing at a missing Massimali row, or a non-matching formula (e.g. `=B3*2`) are each rejected with the right cell named.
6. **Persistence.** Edit maxes, force-quit, relaunch → the maxes and the last week/day are restored.
7. **Programs and revisions.**
   - Import PL28, then import a second program and switch between them: each keeps its own maxes and position.
   - "Aggiorna da xlsx" with an edited copy of PL28 (one prescription changed, one week removed):
     - the change summary shows exactly that
     - the maxes are kept
     - the position is clamped to the shorter program
     - the program id is unchanged
   - Importing an identical file → "già importato".
   - "Ripristina" (restore) an old revision → it becomes current and the history grows by one.
   - A failed update leaves the current revision untouched.
8. **Offline.** With airplane mode on, launch, import and switch weeks: everything works and the fonts are correct.
