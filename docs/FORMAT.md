# Import format: PL28 (format versions 1 and 2)

There are two import formats. This file is the **PL28 format** (accessories fixed per block). The **coach format**
(every session written out) is in `FORMAT-COACH.md`. A workbook with an `accessori` sheet is read as
PL28 format; otherwise one with a `training log` sheet is read as coach format. Both give the same program model.
**Both formats share `Massimali`, `overall`, `note` and `meta`** (since 2026-10-26); they differ only in `accessori`
(here) versus `training log` (coach).

This is the contract for program files. **`fixtures/PL28.xlsx` is the reference implementation.** For a small file to start from or to send to someone,
use `examples/example.xlsx` (10 weeks, 3 days, squat / bench / deadlift only), generated by `npm run example`,
or the empty template (`examples/PL-template-PL28.xlsx`, `npm run templates`, or "Scarica template" in the app).
The parser (`src/parse-pl28.js`) and this document must always agree; if you change one, change the other.

**The file is either accepted completely or rejected.** On rejection the app lists every problem with
its sheet, cell and reason, e.g. `overall!D7: formula non riconosciuta`. A half-read program is never shown.

General rules for every cell: spaces at the ends are ignored, non-breaking spaces count as normal spaces.
Sheet names and headers ignore capitals (`massimali`, `Overall`, `WEEK` are fine); day letters may be lowercase.

## Sheets

| Sheet | Required | Content |
|---|---|---|
| `Massimali` | yes | Lifts and their maxes |
| `overall` | yes | Main-lift plan |
| `accessori` | yes | Accessory exercises |
| `note` | no | Free text, column A, one paragraph per row (empty rows are skipped) |
| `meta` | no | `A1 = formatVersion`, `B1 = <n>`. Missing = format 1. A version newer than the app knows is rejected |
| anything else | ignored | e.g. `volume`, `training log` |

Names ignore capitals and spaces at the ends. Two sheets whose names differ only in capitals (`note` and `Note`)
are an error. **Format versions:** 1 = files without `meta`; 2 = what the app writes (templates and exports), in the
shared `overall` layout. The app reads both; the number only stops an older app from misreading a newer file.

## `Massimali`

- Column A from row 1 down. A **lift row** has a name in A and a number > 0 in B.
- A name in A with nothing in B is a title row and is ignored.
- A name in A with something other than a number > 0 in B is an **error**.
- Reading stops at the row whose A is `Totale` (any capitals), or after two empty rows in a row.
- Lift names must be unique (ignoring capitals).
- Formulas in `overall` point at a lift by its **row**: `Massimali!$B$3`. In PL28: 3 = Squat, 4 = Panca, 5 = Stacco.
- These maxes are the **defaults**. Maxes edited in the app override them; "Ripristina dal file" goes back to these.

## `overall`

The same layout as in the coach format. The older PL28 layout (`week | fase | …`) is still read; see the end of
this section.

**Row 1**
- `A1 = week`, `B1 = giorno`, and a column headed `tipo` (in templates and exports: `C1`).
- Every other headed column is a **slot**: `Name (X)`, where X is the day letter. Example: `Squat stress (A)`.
  Empty columns are separators and are skipped.
- **Column order** is free, but within a day it is the order the lifts are shown in. The app writes them grouped by
  lift (Squat A, Squat C, Squat D, then Panca…, in `Massimali` order, lifts not in `Massimali` last), unless that would
  change a day's order; then it keeps them grouped by day.

**Row 2 (optional): lift types**
- `A2 = tipo alzata` (any capitals), and under each slot its type, free text: `stressante`, `rigenerante`, `tecnica`,
  `stimolo`, `volume`… (templates offer these in a dropdown; any text is accepted). Empty = no type.
- Every week of that slot gets the type; the app shows it as a tag next to the lift's name.
- Without this row (as in `fixtures/PL28.xlsx`) the lifts have no type.

**Then, from row 2 (row 3 after the lift types)**, two kinds of row:

| Row | A | B (`giorno`) | `tipo` | Slot columns |
|---|---|---|---|---|
| **Block row** | empty | block name, e.g. `Blocco 1 – Accumulo` (optional: empty = `Blocco n`) | — | the block's variant for each slot, e.g. `discesa 4''` |
| **Week row** | week number (integer) | the week's dates, free text (optional, e.g. `6-12/10`) | **week type** (list in `FORMAT-COACH.md`): empty = `normale` | the prescriptions |

- A block row is a row with A empty and a name in B or a variant under some slot.
- There must be a block row before the first week (the `Serie B…` columns in `accessori` are per block).
- Weeks are numbered 1, 2, 3… across the whole sheet, with no gaps. `1` and `1.0` are fine, `1.5` is an error.
- The week type must be one of `normale`, `scarico`, `transizione`, `ramping`, `intensificazione`, `picco`, `taper`,
  `entrata`, `test`, `gara` (capitals don't matter). Anything else is an **error**. The app shows it as a badge,
  a pill and a banner. Without a `tipo` column every week is `normale`.
- Blocks can have different lengths. Nothing is fixed to 20 weeks, 4 blocks or 5 days.
- Empty rows are skipped (e.g. one between blocks). **Two empty rows in a row end the sheet**; anything below is ignored.
- A row with A empty and nothing but a week type is an error.
- Merged cells are an error.

**Older layout** (`B1 = fase`, as in `fixtures/PL28.xlsx`): B holds the week type on week rows and the block name
on block rows; there is no `tipo` column and no dates. Everything else is the same.

**Prescription cells** are one of:

1. **Empty**: that slot is not trained that week, and it is hidden.
2. **Plain text**: shown exactly as written (`4@7 + 90% 3x4`, `—`, `TEST`). It may contain load placeholders, see below.
3. **A formula**, which must follow this grammar exactly:

   ```
   formula  := term ( "&" term )*
   term     := string | load
   string   := '"' ( any character, "" for a quote )* '"'
   load     := MROUND(Massimali!$B$<row> * <number> , <number>)
   ```

   Examples:
   ```
   ="4x5 + ist. "&MROUND(Massimali!$B$3*0.57,2.5)&"kg"
   =MROUND(Massimali!$B$3*0.805,2.5)&"kg 30-35RT"
   ```
   - Spaces are allowed, and `$B$3`, `B3`, `$B3`, `B$3` are all accepted. Nothing else is.
   - `<row>` must be a lift row in `Massimali`.
   - The app stores the formula as a template and computes the kg from the **current** maxes:
     `MROUND(x, step) = round(x / step) × step`.
   - A formula outside the grammar is an **error**. The app never falls back to the value Excel cached,
     because that value would ignore the maxes you edit in the app.

### Load placeholders in plain text

For writing programs without formulas: `{<lift name> <fraction>}` inside plain text is a load, rounded to 2.5 kg.

```
4x5 + ist. {Squat .57}kg      → 4x5 + ist. 110kg   (with squat 192.5)
{Stacco 0,795}kg 4x4          → 175kg 4x4          (comma or point both fine)
```

- The name is the lift name as written in `Massimali` (capitals don't matter).
- A name that isn't in `Massimali` is an **error**.
- Braces without a number (`{nota}`) are left as text.

## `accessori`

**Row 1**
- The first six headers, exactly: `Giorno | Esercizio | Istruzioni | Gruppo | Rep | Intensità`.
- Then one column per block whose header starts with `Serie B` (e.g. `Serie B1 (sett 1-5)`), in block order.
  Their number must equal the number of block rows in `overall`.

**Rows 2 onwards**
- The data ends at the first row with an empty `Giorno`; anything below is ignored (PL28 has a footnote there).
- `Giorno`: one letter (lowercase is read as uppercase). The program's days are the letters from the `overall` headers plus these
  (that is how PL28 has a day E with no main lifts).
- Each `Serie B…` cell: an integer ≥ 0. 0 = not done in that block. Empty is an error.
- `Rep` and `Intensità` are prescription cells like those in `overall`: plain text, `{Squat .57}` placeholders or a
  load formula, e.g. `=MROUND(Massimali!$B$3*0.25,2.5)&"kg"`. `Istruzioni` is plain text.
- `Intensità = vedi overall` makes a **volume-only** row: it counts for the volume view but isn't listed
  with the accessories (PL28: weighted pull-ups, already in `overall`).
- Merged cells are an error.

**Light weeks.** In weeks whose type is `transizione`, `scarico` or `test`, each accessory shows one set less
(`sets − 1`) and its intensity `RIR n` becomes `RIR n+1` (`RIR 1-2` → `RIR 2-3`), with a banner saying so.
An intensity that doesn't start with `RIR` (e.g. a load in kg) is left as it is.
An exercise at 0 sets is hidden. Other types don't change sets.

**Display.** Accessories show as `${sets}x${Rep}` (e.g. `3x8-10`), the way the coach format writes them.

## Templates and exports

The app writes files in this format too ("Scarica template", "Esporta come xlsx"): `note`, `Massimali` (lifts from
row 3, then `Totale`), `overall` in the shared layout, `accessori` (headers `Serie B1 (sett 1-5)`, …) and `meta`
(`formatVersion = 2`).
Loads are `MROUND` formulas with the kg already cached, so Excel and Numbers show them straight away; the week-type
cells have a dropdown, the example cells in a template are yellow.

A program can be exported in this format only if the format can describe it exactly: the same accessories, reps,
intensity and variants all through each block, no notes of its own, maxes present. The app checks this by
expanding the result again; otherwise only the coach format is offered, with the reason.
Rows with `Intensità = vedi overall` aren't part of the stored program, so an export doesn't contain them.
